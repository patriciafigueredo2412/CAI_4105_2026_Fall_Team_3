## Final model and verified results

The final model is **engineered-feature Gradient Boosting**. The selected
five-fold model-selection CV RMSE is **$385.05**, with fold
standard deviation **$25.45**. Its mean training RMSE across
those CV folds is $242.09, for a train/CV gap of $142.96.
The gap indicates remaining overfitting. The fitted final pipeline uses all
**7,398** labeled rows and generates prices for all **2,467** test IDs.

This is the team's original modeling approach and parameter search. The final
configuration improves on its original-feature tuned Gradient Boosting and
Random Forest CV results. Tree ensembles can capture nonlinear location and
apartment-size relationships, but cost more to train and are less directly
interpretable than linear models. The notebook includes residual plots and
feature importances to explain model behavior.

The assignment has **no fixed RMSE passing threshold**. Competition performance
is relative to other submissions on hidden test labels. This repository verifies

**1.9.0**. The notebook passes a KFold object to
`TargetEncoder(cv=...)`; support for this was added in scikit-learn 1.9.
See the [official TargetEncoder documentation](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.TargetEncoder.html).

Jupyter. A Windows-only package has a platform marker for other systems.

## Data preparation and validation

The target is `price`. `ID` is excluded from every predictor set and kept for
the submission. The team's code uses bathrooms, bedrooms, square feet, latitude,
longitude, photo availability, and state; it excludes the nearly constant
`category` variable. Numerical features are standardized and categorical features
are one-hot encoded for the baseline/final pipelines. Additional experiments
compare rare-state grouping and target encoding, engineered features, and log
target transformations. Only training labels are used for scoring and tuning.

The original validation workflow has two stages:

1. A fixed **80/20 training-data split** (`random_state=42`) compares all four
   required models plus Ridge and Lasso using training and validation RMSE.
2. **Shuffled five-fold KFold CV** (`random_state=42`) on the labeled training
   data compares the later experiments and supplies Grid Search's scoring and
   final model selection. Pipelines fit preprocessing within each fold.

Scores are compared within their corresponding stage. The initial holdout is
not an independent test of the final tuned model because later CV uses all
training rows. The final CV score is a model-selection estimate and may be
optimistic after searching many configurations. As the original notebook notes,
the later out-of-fold plots are diagnostics, not nested-CV estimates of the
entire model-selection process. Hidden competition prices are never accessed.
